# Supply findings: the observable Austrian data-candidate market on GitHub (collection 2026-09-17)

Evidence document for Layer 2. Every number is copied from `outputs/tables/` (ids in brackets) and refers to a named population: **P_all** = 9,409 Austrian-located GitHub accounts across the three frames; **P_data** = 1,818 of them with a data signal (bio-declared T1 or repo-evidenced T2); **P_T1** = 872 whose bio declares a core data role; **projects** = 6,677 data repositories of P_data meeting the project definition, of which 3,959 documented (README ≥ 1 k) and 2,605 substantive (documented and not educational). Reading rules: these are public GitHub accounts, not the workforce; "any evidence" is the inclusive count, "project-demonstrated" the conservative one; Styria is the only complete regional frame; every Styrian figure is a count. Methodology: `docs/supply-methodology.md`; quality: `docs/supply-data-quality.md`; decisions: `DECISION_LOG.md` D-016–D-021.

## 1. Size and frames (C01, C01a, SQ01, SQ09)

* 1,075 searches → 9,464 unique accounts fetched → 9,457 after dropping 7 organisation/bot logins (`build_supply.py`) → 9,409 with an Austrian location signal (SQ01, C01). Tiers: T0 no data signal 67.8 %, T3 one weak data repo 12.8 %, **T2 repo-evidenced 10.1 % (946)**, **T1 bio-declared 9.3 % (872)**.
* Base rates from the non-keyword frames: among Austrian accounts with ≥ 1 repository, **11–12 % carry a data signal and 2.6–2.9 % declare a data role in their bio** (frame B Styria 12.2 % / 2.6 %; frame C sample 11.3 % / 2.9 %). Frame A (bio keywords) finds the declared ones: 53 % data-signal, 36 % T1.
* Adjacent wording is large: 1,038 accounts (11 % of P_all) describe an ML/AI/data *interest* without a role noun; 335 of them are repo-evidenced (C04a).

## 2. Titles and families (C02, C03, C04, C04b, DS01, DS02)

* Bio-declared families (P_T1 = 872): **data science 73 % (638)**, data analytics 15 % (129), data engineering 7 % (58), business analysis 2 % (21), BI 2 % (15), governance 1 % (7), marketing analytics 2, product analytics 2. Normalized titles: Data Scientist 486, ML/AI Engineer 140, Data Analyst 124, Data Engineer 55, Business Analyst 21, BI Developer 15, Statistician 12.
* Against Layer 1 demand shares (data engineering 22 %, data science 22 %, business analysis 17 %, analytics 15 %, BI 12 %, governance 9 %): relative representation of bio-declared supply = **data science 3.3×, analytics 1.0×, engineering 0.30×, BI 0.15×, business analysis 0.14×, governance 0.09×, marketing analytics 0.07×**. GitHub bios over-state "data scientist" relative to the titles employers advertise and under-state everything that runs on SQL Server, Power BI, SAP or requirements documents.
* Fragmentation: 574 distinct raw bio openings among 764 parsed (normalised entropy 0.94; top phrase "data scientist" only 6 %); after normalisation 13 titles (entropy 0.55, top-1 56 %). Candidates describe themselves in many ways, but they map onto few families.
* Titles employers use that almost nobody declares on GitHub: BI Analyst (32 ads / 0 bios), BI Consultant (20 / 0), Data Architect (21 / 0), Master/Product Data Management (34 / 1), Financial/Risk Analyst data-heavy (30 / 5), Marketing/CRM Analyst (22 / 2).
